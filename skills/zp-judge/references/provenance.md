# 来源与边界

## 这个技能参考了什么

方法从下面几处取思路，**用自己的话重新写成，没有复制任何一段原文**。

| 步骤 | 参考的做法 | 来源 |
|---|---|---|
| 钉决定、先钉可观察的现象 | 把问题改成可观察、可验证的说法，再谈解释 | dbskill 中的好问题、诊断类 Skill（作者 dontbesilent） |
| 信息不够时不硬凑，先给取数据的动作 | 证据不足就不编解释，改为给出一个能拿到数据的具体动作；反对用反复准备代替动手 | dbskill 的好问题、诊断、行动类 Skill |
| 分层定位、未知就写未知 | 低流量按曝光、停留、持续观看、互动关注、承接分层；数据不全的层不补猜 | dbskill 的内容价值评估 |
| 平台阈值当待验证假设 | 算法与完播阈值只作假设，不当事实 | dbskill 的短视频简报 |
| 失效条件、结果回填不倒灌后见之明 | 写“什么条件下判断会变”；自己的结论与 AI 推测分开标 | dbskill 的判断路径、决策档案类 Skill |
| 反方先行 | 见 references/counter-argument.md 的研究依据 | Sharma 等 2023；Nemeth 等 2001；Schweiger 等 1986；Murrell 等 1993 |

## 我们自己补的（dbskill 里没有看到的）

- 样本量与区间：用 Wilson 区间读小样本。
- “只改一个变量”的实验设计，和“观察前先定判断线”。
- 反方协议：两边都反驳、异议必须带事实并写出怎样检验、最多五条、按是否改变决定排序。
- 三种结论的准入条件（结构性缺口／信号大于噪声／零成本可撤回且能产生信息），以及“不许只写再等等”。

## 和 zp-question 的关系

`zp-question` 解决“说不清、不会写给 AI”；`zp-judge` 解决“想不对、不必要、证据弱”。必要性闸门（references/necessity-gate.md）是我们自己补的，dbskill 的好问题技能里有判断任务能否由 Agent 解决的思路，我们把它扩成六项检查和三种结论。

## 边界与署名

- 思路参考了 dbskill（作者 dontbesilent，采用 CC BY-NC 4.0）里关于提问、诊断与内容评估的做法。本技能是对一般决策方法的独立表述，没有复制其文本，与该作者没有隶属关系；若你要再分发或商用其中参考的部分，请直接查看该项目的许可条款。
- 它是方法，不是预测。它不替你判断平台算法、不保证结果；证据少时它的作用是让你知道该做哪一步、做完看什么。
- 反方协议不适合可撤回的小事，也不能替代真人的反对意见。
