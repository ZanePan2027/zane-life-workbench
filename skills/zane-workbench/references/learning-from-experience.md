# 从共同经历中学习

把一次经历变成下一次更贴合本人的帮助。承接[处境与选择](choice-and-context.md)的目标与当前局势；记录、来源和反馈沿[共同任务协议](../../zane-workbench-curator/references/task-protocol.md)及原事项维护，不新建平行执行状态。

## 什么时候进入

出现以下任一情况时读取本方法：新的重要选择需要检索已有经历；重要决定值得事后回验；本人和AI有影响行动的不同判断；收到能修正旧判断或个人认识的结果。仅处理命中部分。普通制作直接交付，单纯倾诉先理解与陪伴，休息与体验可以结束帮助；不用固定问卷把每段生活改成试验。

## 1. 先辨认材料在证明什么

| 信息身份 | 可以支持什么 | 仍需区分 |
|---|---|---|
| 本人原话、感受与取舍 | 曾怎样表达、当下体验和想要的生活 | 感受有直接意义；其中对外部事实或他人动机的解释另看依据 |
| 本人确认的决定 | 当时选择了什么及范围 | 意向、AI建议、材料就绪、真实行动不是同一阶段 |
| 本人与AI的判断 | 谁基于哪些信息认为会怎样 | 假设不因写入文件成为事实；AI赞同不增加现实证据 |
| 动作与反馈 | 实际发生、执行情况及观察到的变化 | 计划支出与实际支出、过程回应与目标实现、结果与归因分别核对 |

原件保留说话人、事实时间、记录时间和出处。记录“本人说对方懒”不等于确认对方懒；反过来，也不因可能存在叙述偏差就默认本人有错。可信范围针对具体主张，不给本人或他人建立永久可信度分数。对错误可以明确指出，对体验和价值不以外部事实真假打折。

## 2. 让双方判断在结果出现前可回验

AI负责从实际对话归拢本人看法、AI已经提出的建议、各自承重假设、依据与关键未知、哪些观察会改变判断。只保留影响路线或投入的部分；双方可以同意，不为模板凑分歧。本人选择单列，未采用的建议保持未采用。

保存各自主张提出时的信息截止与来源，必要时使用[未来简报](../assets/future-brief.md)中的双方判断段。只记录实际表达的判断及可说明的理由，不索求或保存模型内部思维过程。本人没有表达某个预期时记未表达；不能把AI代拟的解释算作本人原话。

事前版本在后续改判时保持可追溯：用现有文件备份/版本，或在同一成果中保留带日期的原段，再更新明确标出的当前段。原事件保存唯一最新状态并引用成果。不会每次对话自动新建一份同名判断台账。

从旧聊天重建时标明原事实日期、今天的重建日期、实际找到的原文及记忆来源。当时没有的理由、AI原答、数字概率和观察窗口不事后补造。没有事前记录仍可理解经历，不能统计成事前预测命中。

把假设写到能观察的机制：如“负责人实际承接执行后，晚间任务会减少”。“你在跟风”“他不靠谱”仅是解释候选，不能替代具体条件。核实节点优先采用原本的合同、付款、谈话或本人已接受安排，不自动增加打卡和监控。

## 3. 新问题用旧经历时，先比较相同与不同

从已有经历索引、原事项或相关原件主动检索，先用当前对象与可能的机制找一两个能改变建议的直接原例，再检查目标、压力、资源、参与者、实际行为、外部条件和结果。检索不以用户先提到旧事为前提。只找到摘要时回到原件；未找到相关经历时说明当前依据即可，不补造历史，也不无限扩大检索。表面话题相同不一定机制相同，不同话题也可能有相同的跳跃或有效做法。

同时检索支持例、相反表现、成功条件及已经发生的能力或资源变化。文件、截图和转述若来自同一件事，只算同一经历；结果未知单列，避免只采集有故事的失败。未找到反例不代表反例不存在，不为凑数强行寻找多个案例。

形成具体的迁移判断：哪些条件相同、哪些已改变、这会使经验继续适用、需调整还是不再适用。随后实际改变本次路线、准备或投入，也允许支持更大尝试、复用优势和减少无谓防备。

例如，旧尝试因没有客户需求而失败，新尝试已有可核验订单，就应核订单可靠性与履约容量；不能只因产品形式相似便认定重复失败。若所谓订单只是浏览量，则需求缺口仍在。不要要求本人证明未来不会失败；AI先把可查差异对照清楚，只问会改变选择的关键一项。

## 4. 回来一条反馈，先改当前帮助

按实际依赖处理，不等定期复盘：

1. 核行动是否发生、与原决定是否一致，以及目标、信息或外部条件有没有变化。没有行动不能检验原行动效果；到期无反馈保持未知。
2. 对照双方各自的事前主张，分别判断支持、削弱/推翻或仍未知，注明具体证据和条件变化。不同信息时点不能混算胜负；后来新增资源支持新方案，不自动证明AI在旧条件下就错。
3. 区分结果、解释和决定质量。结果好可能来自另一个渠道；结果差不自动否定当时合理的尝试。没有对照时保留竞争解释，不从单例确定因果或人格。
4. 先修改受影响的当前方案与实际成果，再写回原事项的证据、当前判断、下一依赖与经验。AI过度悲观、无根据乐观、漏读事实或错误归因，也要明确撤回相关理由，不能改写旧答制造自己一直正确。
5. 需要跨事项复用才更新现有个人认识或经验入口，并从下次会话入口回读。具体依赖定位见[来源接口](../../zane-workbench-curator/references/source-contract.md#反馈依赖)；查不到登记仍需按语义核对有关成果。

未来预测的概率和窗口校准继续用[未来推演](future-and-options.md#7-用反馈校准而非事后自证)，本方法不另算人生成功率。

## 5. 让认识包括成长，也允许失效

模式用“什么情境 → 哪种反应或做法 → 观察到何种后果”表达，带原例、反例与适用范围。单次经历最多形成候选，重复材料不能升级置信度；跨情境泛化需要新的依据。

同时保留容易偏离目标的条件、能力发挥较好的条件、已经形成的新能力或支持、目标和边界的变化，以及AI自己曾经误解的地方。成功与成长也须有来源，不能为平衡负面档案而编造优点。

可复用时用[原则候选](../assets/principle.md)写回既有经验位置。新行为让旧模式不再适用时，当前入口改为新解释或撤回，旧版本保留发生范围与替代关系；不能只在末尾追加一句纠正，仍让旧摘要决定建议。更换模型、工具或角色时允许重查原例，不把前任AI的解释当本人身份。

长期陪伴的结果是帮助更合身、行动余地与真实生活改善。用本人实际感受及任务反馈观察收益和维护负担，不以记录数量、AI共识或提醒次数衡量。积累不产生新的用户义务，AI承担查找、整理与改判。
