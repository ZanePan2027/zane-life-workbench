# 工作台结构

目录服务同一条主链：方向→阶段→局势→路线→行动反馈→认识更新。首次建台使用当前任务的够用结构；用户要求完整工作台或全面重构时，按下表组织所有现有材料与运行入口。

| 职责 | 推荐位置 | 内容 |
|---|---|---|
| 每日入口 | README或工作台导航 | 当前重点、成果、暂停点及其他入口 |
| 生活方向与阶段 | 方向与取舍 | 本人目标、取舍、当前关键障碍与转折 |
| 本人认识 | 个人底图 | 本人原话、经历、偏好及相关生活领域 |
| 局势和计策 | 局势与推演 | 人物与组织、资源、环境、路线、经验修订 |
| 唯一执行状态 | 事项或已有事件目录 | 已发生、已选、在等什么、下一依赖及反馈 |
| 原件和成品 | 资料或已有资产目录 | 原材料、可用草稿、计算、研究和资产 |
| 进入材料 | 收件箱或现有资料入口 | 待读的新材料及归位入口 |
| 协作和运行 | 协作与运行 | 角色、信息沉淀、接力与维护 |
| 历史 | 已有历史目录 | 被替代版本及恢复点 |

这些是职责映射，已有项目采用自身名称；新增空工作区可以从最小模板开始。完整life模板提供上述导航，个人内容从真实任务写入。新建源与成果必须接到来源映射、当前导航和对应事项；不会只增加文件夹。

## 全面重构的执行顺序

1. 读取用户目的、现有规则、当前任务及全部目录清单。识别原件、当前判断、生成页、方法、宿主入口、历史与构建副本。
2. 确定每类信息唯一当前位置；沿用可靠的事件和来源工具。列迁移映射、影响范围与恢复办法，备份实际变化对象。
3. 按映射移动，更新相对链接、配置、脚本、事件引用与主导航；旧路径按实际依赖保留兼容入口。原件与语义不因搬迁改变。
4. 整合角色共同规则与重复状态；路线呈现当前判断，旧分支归历史。完成本轮实际所需成品并挂到事项入口。
5. 用真实链接和正文检查迁移；以独立新会话从首页找到方向、人物、路线、成果与实际暂停点。变更事实后走一遍当前方案修订和接续。
6. 保存迁移记录、检查与可执行恢复方式。之后的反馈按新结构更新。

## 路线与成果

重要选择一份当前路线：服务的生活目标、阶段矛盾、局势、可行主备路、时间空间、转向信号、直接可用材料。执行状态仍由原事项维护，路线引用原事项。事项可登记成果链接，用户从首页直接打开成品；普通证据和成果分别连接。

值得回验的双方判断与信息截止放在这份路线中，保留可追溯事前版本；反馈修改当前段与原事项。跨事件认识归已有个人底图或经验位置，标记条件、反例、成长和撤回关系。无需为每个决定另外创建两份文件或新的状态库。
