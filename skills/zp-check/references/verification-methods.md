# 核实方法：按产出类型怎么独立确认

原则：核实动作落在 AI 之外的东西上，看到的是产出本身。

| AI 的产出 | 不能算证据的 | 可以算证据的做法 |
|---|---|---|
| 说“已发布／已保存／已发送” | 工具打印的“成功”、AI 的“✅” | 打开对应的页面、列表或收件箱，看那条东西是否真在、内容是否一致；数量对得上 |
| 修改了文件／文档 | “已按你的要求修改” | 打开文件，对照你的要求逐条看；或对比修改前后的差异 |
| 给了事实、数字、日期 | AI 的语气肯定、有“研究表明” | 打开来源原文，确认原话里确实有这个数；没有来源就当 [推] |
| 给了分析或结论 | 条理清楚、看起来有道理 | 挑出一两条最关键的前提，单独核实；看它有没有区分事实与推测 |
| 给了一堆建议 | 每条都很合理 | 按“能不能很快验证”排序，先做最便宜的一条看现实反馈，别逐条相信 |
| 说“我已经检查过了” | 这句话本身 | 让它列出检查了什么、结果是什么；你自己抽查其中一项 |
| 写了代码或脚本 | “运行成功” | 自己跑一遍，用一个已知答案的输入验证；看产出而不是日志 |

## 让核实更便宜的几个办法

- **读回**：写入后立刻读出来，和预期对比。
- **抽查**：不必全核，抽最关键的两三条；抽到错就扩大范围。
- **新对话复问**：把同一问题放进一个没有上文的新对话，看答案是否一致。一致只说明它稳定，不说明它对；不一致说明至少有一边靠不住。
- **找真人**：目标读者或同行看一眼，比 AI 自查可靠得多。
- **先小后大**：先在一小份上试，再放大。

## 复核本身的成本

核实要花时间。按“出错的代价 × 难撤回程度”决定核多深：可撤回、代价低的，看一眼；要对外发布、涉及钱、关系或不可逆的，逐条核。
